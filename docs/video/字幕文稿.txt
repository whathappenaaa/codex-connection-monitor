所以我做了一个 Windows 桌面小工具，叫 Codex 连接灯。

今天给大家实际演示一下，也把完整源码免费开源出来。

大家好，我是那年松江。

这个工具的起点，就是我自己使用 Codex 时遇到的一次连接中断。

我提出需求，使用 Codex 辅助开发，再根据实际使用情况调整任务名称、窗口大小和中英文切换。

现在又加上了剩余额度和更明显的托盘颜色。

先看上面这一块，它对应的是正在监测的任务。

可以自动跟随，也可以手动选定一个任务。

绿色表示最近收到模型输出，或者日志里出现了连接成功的记录。

它说明最近有成功的证据，不保证接下来一直在线。

红色表示近期出现了明确的连接中断或者重试。

黄色表示之前失败过，恢复还没有确认，或者网络探测发生了异常。

灰色表示证据不够。

接下来做一个真实测试。

我先确认 Codex 正在输出，然后手动把网线拔掉。

这里不保证拔线的一瞬间就变色。

系统、请求和日志发现问题都需要时间，我们看实际结果。

出现红色：现在已经显示红色了。

把鼠标放上去，能看到这次是本机网络不可用，还是任务出现了重试。

这里按实际显示的原因判断。

仅出现黄色：这次先看到的是探测异常，暂时没有足够的任务中断证据，所以显示黄色。

没有发生中断：这台电脑可能还有其他可用网络，或者这次没有捕捉到明确的异常，因此这段不能当作成功复现的断网结果。

现在接回网线。

入口恢复，并不表示刚才的对话已经继续。

我们还要看 Codex 有没有新的输出。

如果那次请求已经结束，就重新发一个简单请求，再观察状态。

这里是账号共享的剩余额度，不是当前这一个任务单独的额度。

接口返回几个周期，软件就显示几个，不会所有人都固定显示五小时和每周两条。

百分比来自官方账号接口，旁边是按电脑本地时间显示的重置时间。

它会定期刷新，也可以手动检测。

断网时如果更新失败，会保留上次结果并标记旧数据，不能把旧数字当成实时余额。

到了重置时间，也要重新查询确认，不会自己假定恢复满额。

额度用尽或者查询失败，不会让连接灯变红，因为这和网络断线是不同的问题。

平时我更喜欢用小号。

顶部的小、中、大可以直接切换，想看详细说明就用中号或者大号。

自适应会根据内容调整高度。

如果你自己拖动边框，就会停止自动调整，避免程序覆盖你的操作。

再次点击尺寸按钮，就能恢复。

右上角可以切换中英文。

自动跟随不是想看的任务时，也可以手动选择。

关闭窗口会继续留在托盘。

彻底退出，要从托盘的右键菜单退出。

没有返回额度数据时，会说明原因，不会显示一个假的零。

更新时先退出旧程序，再解压新版。

以后不想用了，从托盘彻底退出，再删除解压目录即可。

它会只读分析本机的 Codex 日志和任务名称，并通过官方 Codex 查询账号额度。

连接灯不保存账号令牌，不发起模型任务，也没有上传聊天内容的功能。

另外，它会定期探测微软和 ChatGPT 的公共入口，所以不是完全离线的软件。

它不能修复代理、服务器或者 TLS 错误。

连接判断依赖本地日志，Codex 更新后可能需要适配。

遇到证据不足的时候，正确的表现就是显示未知。
